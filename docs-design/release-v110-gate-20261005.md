    서버 값 리셋 점프, Codex 설치·로그인 메뉴 (사양 `docs-design/server-only-usage-20261005.md`).
  - 릴리즈 커밋 뒤 수정(Windows 실기기 검증에서 나온 결함): `71dc340`, `68fb6dd`, `139669d` — Codex 토큰 만료 표시,
    일시 오류 때 직전 서버 값 유지(리셋 지난 레인 제외, 그동안 재학습 없음), 설정 저장이 필요할 때만 재조회,

## 항목 1–3 — 게이트 증거
1. **깨끗한 트리에서 전체 스위트 (끝 커밋의 프로덕션·테스트 바이트 = `7b72775`).**
   - 검증자 rel110-verify, `7b72775` 에서: `python3 -m unittest discover -s tests` → `Ran 1042 tests — OK (skipped=8)`,
     `python3 -m unittest discover -s windows/tests -t .` → `Ran 265 tests — OK (skipped=23)`.
     첫 실행에서 샌드박스 감시 테스트 1건이 실패했는데, 사용자의 설치본 ClaudePet 이 실행 중이라 `~/.claude_pet.json`
     의 수정 시각이 바뀐 것을 잡은 것이다(크기 동일). 그 클래스만 세 번, 전체를 한 번 더 돌려 OK. 코드와 무관한 실패다.
   - CI run 37325484490 (`7b72775`): macOS 전체 스위트 성공, Windows 게이팅 계약 성공.
   - 이 기록 커밋은 `docs-design/` 의 문서 하나만 더하므로 스위트 결과에 영향이 없다.
2. **먼저 빨강 (red before green).**
   - 기능: `bf25e95`(163 실패·4 오류), `8dfc8ba`(71 실패·15 오류) — 구현 전 관측. 기능 머지 전 CI 양 작업 성공.
   - v1.1.0 계약 `tests/test_v1_1_0_release_contract.py`: a991e6c 에서 9 실패, 릴리즈 커밋에서 노트 문장 1건 실패 → 정정 뒤 통과.
   - 회복력 `tests/test_server_value_resilience.py`: `8bcb8ba` 가 71dc340 이전 코드에서 22 실패·4 오류,
     `6c9cc01` 이 71dc340 에서 8 실패, `e02bffd` 가 68fb6dd 에서 2 실패. 각 수정 뒤 통과.
3. **릴리즈 노트 확인.** 최상위 불릿 3개, 중첩 없음, 394자(정규화), 해시·경로·테스트 언급 없음, 크기·빈도의 모호한 표현 없음.
   문장마다 계약 테스트가 소스에 묶는다(검증자 rel110-verify, 검토자 rel110-review 확인).

## 항목 4 — 조정자 서명
- **분리:**
  - 기능 변경: 개발자 sou-dev(프로덕션·문서), 검증자 sou-verify(테스트만), 검토자 sou-review(1차 수정 필요 → 2차 승인, 사소한 지적).
  - 릴리즈: 개발자 rel110-dev(프로덕션·노트·문서), 검증자 rel110-verify(테스트만), 검토자 rel110-review(수정 필요 2회 → 3차 승인, 사소한 지적).
  - CI 워크플로 수정(`591d149`, `3294d09`)은 조정자가 했다. 출하되는 파일이 아니다.
- **실기기 확인:**
  - Windows 11 실기기(사용자 PC): 1차(`4c088dc`)에서 결함 4건 — 검증 세션 보고 3건(ja 팝업 잘림, Codex 토큰 만료 때
    줄이 조용히 사라짐, 설정 저장 뒤 429 로 숫자가 사라짐)과 조정자가 스크린샷에서 찾은 1건(구역 제목 크기) —
    2차(`139669d`)에서 모두 고쳐짐.
    빌드 게이트 통과, 빌드본 실행 확인(필 표시, 우클릭 메뉴의 `ClaudePet v1.1.0`). 보고서는 조정자 스크래치패드의 `win110/`.
  - macOS: 조정자가 최종 코드를 소스로 띄워 설정 창 4개 언어와 필을 눈으로 확인했다(en/es 잘림은 `b3ddbba` 로 고쳐짐).
    소스 실행에서는 제공자 로고가 그려지지 않는데, 배포 중인 v1.0.1 소스에서도 같고 설치된 번들에서는 그려진다 — 이번 변경과 무관.
- **인증:** v1.1.0 을 실행 단계에 들어가도 된다고 인증한다.
- **확인하지 못한 것:**
  - Developer ID 서명·공증된 v1.1.0 번들의 실행(운영자가 빌드한 뒤에야 존재한다).
  - 실서버가 429 를 준 상태에서 숫자가 유지되는 장면(Windows 에서 가짜 응답으로 실제 조회 함수를 확인했다).
  - 실제 Codex 사용량 줄: 이 Windows PC 의 Codex 토큰이 401 이라 만료 안내만 확인했다. macOS 에서는 Codex 줄이 보였다.

## 항목 5 — 릴리즈 운영자
- **자격 없음:** 조정자(이 세션); sou-dev, sou-verify, sou-review; rel110-dev, rel110-verify, rel110-review;
  Windows 검증 세션; 이전 릴리즈·사이트 작업의 모든 에이전트.
- **지정 운영자:** `release-operator-v110`. 이 파일이 커밋된 뒤 이 일 하나만을 위해 만든다.
  - `./release.sh build`, `sign`, `notarize`, `universal`, `dmg`, `publish` 를 하나씩 실행한다.
  - `all` / `ship` / 맨 `./release.sh` 는 절대 실행하지 않는다.
  - 단계마다 결과를 기록하고 첫 실패에서 멈춘다.
- **Windows 산출물:** 사용자 Windows PC 에서 `139669d` 로 만들었다(무서명, 원래대로). 이 기록 커밋까지의 차이는
  테스트 핀 두 줄과 이 문서뿐이라 출하 바이트(`claude_pet.py`, `windows/`)는 같다. 조정자 스크래치패드 `win110/` 에 있다:
  - `claude-pet-win.zip` 72,629,358 바이트, `6dc425b54766cff233c302e29d91fdf10cd58a1acf1437e4f7aff589d1880403`
  - `claude-pet-win-setup.exe` 56,158,487 바이트, `1305a395586a7965f42ba2344f29d8705580e9855177925eeee9305561744846`
  운영자는 해시를 다시 확인한 뒤 같은 릴리즈에 올린다(`--clobber` 없음).
